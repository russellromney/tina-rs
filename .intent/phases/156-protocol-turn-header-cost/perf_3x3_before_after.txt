# Phase 156 — 3x3 before/after perf evidence (macOS/aarch64 + Linux/x86_64)

The hard performance proof for item 8. Three before runs and three after runs on
each platform.

- BEFORE = pristine `main` (f96160c). The macOS/Linux before binaries carry one
  test-only change — the item-8 print-reorder so the gRPC latency rows reach
  stdout (on `main` the perf test panics on the connection-setup leak check
  before printing them). Measured code (tina-http, runtime) is pristine `main`.
  Verified "really before" by warmed-unary process allocations ~3953 (macOS) /
  ~4070 (Linux), not the after ~2880.
- AFTER  = `phase-156-protocol-turn-header-cost` @ item 3 (commit a17444d):
  items 1/2/3/4/5/6 + item 7.

Workload: `native_protocol_rows`, WORKERS=4, PROTOCOL_OPS=32, median-of-five per
row. Process allocations = whole process (client + server) over the load run.
macOS = Apple Silicon laptop. Linux = Fly `performance-2x`, region iad,
dedicated CPU (app `tina-perf-150`). Counts below are medians across the 3 runs
(each run already medians five samples per row).

## Targets

- warmed gRPC unary process allocations >= 20% lower: **MET** (-30.9% macOS,
  -31.9% Linux).
- warmed gRPC server-streaming >= 15% lower: **NARROWLY MISSED at the median**
  (-14.2% macOS, -13.7% Linux). The client inline-frame zero-copy follow-on moved
  this from -11.8%/-11.4% to within a point of target; individual macOS runs cross
  15% (min 4478 = -15.8%). The remaining residual is the per-pull `call_blocking`
  machinery (runtime — streaming pays ~2 extra host round trips vs unary), not
  protocol framing. Closing the last point needs a runtime change to per-pull
  cost, the same class of wall as the unary turn-floor. Recorded honestly rather
  than reworded to look met.
- HTTP/2 steady-state lower-or-equal, no regression: **MET** (0% both platforms).
- p90/p99 within 10%: **MET** (after p50/p90/p99 at or below before on steady
  rows).
- at least one warmed protocol/app turn-count row improves: **MET** (all three:
  unary 17->13, http2 11, streaming 21/22; saved in turn_reduction_timelines.txt).

The headline target — warmed gRPC unary, named the phase's first target — is met
and exceeded on both platforms. The server-streaming sub-target is the one gap.
